# 군중 사진 사람 검출: 모델 선택 및 파인튜닝 권고 (CrowdHuman 평가 검토)

대상: CPU 서비스 (i7-1165G7, ONNX Runtime), 재현율 최우선, 오검출 허용, 지연 1 s 이하, Apache-2.0 선호, 파인튜닝 예정.
근거: eval_results.json, summary.md, metrics.py / run_eval.py, 검토자 추가 계산 `bench/eval/out/review_extra.py`
(out/cache 의 원본 검출 score>=0.05 사용, 이미지 단위 짝지은 부트스트랩 2000회, seed 0).
데이터: CrowdHuman val 100장 (사람 15명 이상), GT 3607명, 전신 amodal 박스. 모든 수치는 IoU 0.5 기준임.

## 1. 결론

- **현재(파인튜닝 전) 최선: YOLOX-m.** 같은 FPPI 에서 재현율이 1위이거나 동률임. FPPI 2/5/10 에서 각각 30.6 / 41.4 / 49.4%,
  잘 보이는 사람 재현율(vis>=0.5, 높이>=32px)은 FPPI 2 에서 42.0%. 지연은 414 ms 로 RT-DETR-R50vd(994 ms)와 동률이면서 2.4배 빠름.
- **파인튜닝 대상: RT-DETR-R18vd (대안: YOLOX-m).** 지금은 YOLOX-m 보다 2.5pp 낮음(유의). 그래도 NMS 없이 끝단에서 바로
  박스를 내는(end-to-end) 구조라 겹친 사람을 NMS 가 지우는 상한이 없음. 가장 빠르고(384 ms) Apache-2.0 이며, 공식 학습 코드와 ONNX 내보내기가 있음.

## 2. 지표 타당성 (어떤 지표로 고를 것인가)

**(A) 비교 기준은 '같은 FPPI 에서의 재현율'(FPPI 5~10)이어야 함. 고정 conf 재현율로는 모델을 비교할 수 없음.**
- 모델마다 점수 척도가 다름. conf 0.10 에서 FPPI 는 RT-DETR-R18 41.5, RT-DETR-R50 31.0, DETR 19.3, YOLOX-m 8.8.
  그래서 recall@0.10 (R18 61.4% vs YOLOX-m 47.6%)은 사실상 오검출을 4.7배 더 허용한 결과임.
- 버킷 표(conf 0.25/0.10)도 마찬가지임. 각 모델을 FPPI=5 임계값에 맞추면 차이가 거의 사라짐.
  예: vis<0.5 재현율은 YOLOX-m 7.7, R50 7.7, R18 9.0, YOLOX-x 6.8, DETR 7.2%.
  conf 0.10 에서 보였던 R18 31.1% 대 YOLOX-m 10.9% 차이는 운영점(FPPI)이 달라서 생긴 것임.
- 군중 사진 1장에 평균 36명이 있으므로, 재현율 우선 서비스의 현실적인 운영점은 FPPI 2 보다 5~10 쪽임.
  FPPI 2 는 CI 폭이 약 ±5pp 로 넓어 보조 지표로만 쓸 것.

**(B) AP50 순위(RT-DETR 이 +5~8pp 로 유의하게 앞섬)는 재현율 우위를 뜻하지 않음.**
- 같은 FPPI(≤10)에서 RT-DETR-R50 과 YOLOX-m 의 차이는 0.1~0.6pp 로 유의하지 않음.
- AP50 차이는 곡선 끝(저점수 구간) 길이에서 나옴. YOLOX 는 adapter 의 conf 하한 0.05 에서 곡선이 끝나지만 (FPPI 11.5, 재현율 50.8%),
  RT-DETR 은 FPPI 51~59 까지 이어짐. 실제로 YOLOX-m 을 conf 0.01 로 다시 돌리면 AP50 이 42.5 → 44.8 로 오르고,
  최대 재현율도 50.8 → 55.4% (FPPI 22)로 오름.
- MR-2 (FPPI 0.01~1 구간)는 모든 모델이 92.9~94.8 로 거의 같고, 재현율 우선이라는 목적과 맞지 않음.

**(C) 재현율 상한 점검: max-dets 100 과 NMS 는 FPPI≤10 결과를 바꾸지 않음.**
- harness 의 MAX_DETS=100 때문에 RT-DETR 검출이 잘림 (R18 은 86장, R50 은 59장에서 100개 초과).
  다만 잘리는 것은 점수가 낮은 꼬리라서 FPPI 2/5/10 재현율은 cap 1000 으로 바꿔도 소수 첫째 자리까지 같음.
  바뀌는 것은 최대 재현율뿐임 (R18 63.9 → 67.3%, FPPI 87).
- DETR-R50 은 쿼리가 100개여서 구조적으로 이미지당 100명이 상한임 (표본 최대 148명).
- YOLOX-m 의 NMS IoU 를 0.45 → 0.6 → 0.7 로 올려 보았음 (conf 0.01, 메모리 내 재추론).
  FPPI 2: 30.6 → 30.3 → 30.3%, FPPI 10: 49.4 → 48.6 → 48.2% 로 같은 FPPI 에서는 이득이 없음 (살린 사람만큼 중복 박스가 오검출로 늘어남).
  오검출을 크게 허용할 때만 최대 재현율이 55.4 → 60.2% (FPPI 39)로 오름. NMS 계열은 군중에서 이 trade-off 를 피할 수 없고, 이것이 파인튜닝 대상 선정의 핵심 근거임.

**(D) 잘 보이는 사람 기준 재현율 (vis_ratio>=0.5 & 높이>=32px, n=2522)**
- 전체 GT 와 같은 매칭과 같은 오검출 정의를 쓰고, 재현율만 이 부분집합에서 계산함.
- FPPI 2: YOLOX-m 42.0, R50 40.4, R18 39.1, YOLOX-x 38.5, DETR 35.6%.
- FPPI 10: YOLOX-x 65.9, YOLOX-m 65.5, R50 65.3, R18 60.8, DETR 58.2%.
- vis<0.5 (1039명)은 모든 모델이 FPPI 5 에서 7~9% 만 찾음. 사전학습 모델로는 거의 못 찾는 영역이므로 파인튜닝으로 개선할 대상임.

## 3. 통계적으로 유의한 차이 (짝지은 부트스트랩 95% CI 가 0 을 포함하지 않음)

- DETR-R50 은 FPPI 5/10 에서 나머지 4개 모두보다 유의하게 낮음 (-2.4 ~ -5.3pp). 잘 보이는 사람 기준으로도 R50·R18·YOLOX-m 보다 낮음.
- RT-DETR-R18 은 FPPI 5/10 에서 YOLOX-m(-2.5/-2.6), YOLOX-x(-2.6/-2.8), R50(-1.9/-2.5)보다 유의하게 낮음.
- YOLOX-m, RT-DETR-R50, YOLOX-x 는 FPPI 5/10 에서 서로 구분되지 않음 (|차이|≤0.7pp).
  FPPI 2 에서는 YOLOX-m 이 YOLOX-x 보다 +2.5 [+0.7, +4.3]pp 높고, 잘 보이는 사람 기준으로는 +3.3 [+0.9, +5.9]pp 높음.
- FPPI 2 에서 YOLOX-m 과 RT-DETR 두 모델의 차이는 유의하지 않음 (+1.1 [-1.5, +3.8], +1.8 [-0.4, +4.3]).

## 4. 순위 (파인튜닝 전, 같은 FPPI 재현율 + 지연)

| 순위 | 모델 | FPPI 2 / 5 / 10 재현율 | 잘 보이는 사람 @FPPI 2 | 지연 중앙값 | 비고 |
|---|---|---|---|---|---|
| 1 | YOLOX-m | 30.6 / 41.4 / 49.4 | 42.0 | 414 ms | 1위 또는 동률, 빠름 |
| 2 | RT-DETR-R50vd | 29.4 / 40.8 / 49.2 | 40.4 | 994 ms | YOLOX-m 과 동률이지만 1 s 한계 |
| 3 | YOLOX-x | 27.9 / 41.3 / 49.7 | 38.5 | 1522 ms | 지연 예산 초과, FPPI 2 에서 YOLOX-m 보다 유의하게 낮음 |
| 4 | RT-DETR-R18vd | 28.6 / 38.9 / 46.6 | 39.1 | 384 ms | FPPI 5/10 에서 상위 3개보다 유의하게 낮음 |

## 5. 파인튜닝 권고: RT-DETR-R18vd (대안: YOLOX-m)

**R18 을 고른 이유**
- 이유 1 (구조): 사람이 겹치는 군중에서 NMS 는 재현율의 상한을 만듦. 위 (C) 에서 NMS IoU 를 바꿔도 같은 FPPI 에서는 개선이 없었음.
  RT-DETR 은 set prediction 으로 중복 제거까지 함께 학습하므로, 군중 데이터로 학습하면 이 상한이 없음.
  (이 부분은 구조에 근거한 판단이며 이번 데이터로 검증한 것은 아님.)
- 이유 2 (지연): 5개 중 가장 빠름 (384 ms). 그래서 입력 해상도를 640 → 800 정도로 올려 작은 사람(32~96px)의 재현율을 높일
  지연 여유가 있음. R50 은 지금도 994 ms 라서 여유가 없음.
- 이유 3 (생태계): lyuwenyu/RT-DETR (Apache-2.0) 에 COCO 사전학습 R18 체크포인트, COCO 형식 커스텀 데이터 학습, ONNX 내보내기가 공식으로 있음.
  20M 파라미터라 단일 소비자 GPU/Colab 으로 학습할 수 있음. 학습 시간은 이번에 측정하지 않았음.

**대안 YOLOX-m**: 현재 가장 강하고 학습 레시피가 가장 단순함 (Megvii YOLOX, Apache-2.0, exp 파일 하나로 COCO 형식 학습).
R18 파일럿이 YOLOX-m 기준선을 넘지 못하면 YOLOX-m 으로 전환함.

**설정 권고**
- 단일 클래스(person)로 학습하고, COCO R18 체크포인트에서 시작함.
  num_queries 를 300 → 500 으로 늘림 (군중 이미지는 100명을 넘는 경우가 있음).
- 학습은 multi-scale, 640~800 으로 함. ONNX 내보낸 뒤 i7-1165G7 에서 800 입력 지연을 실측하고, 1 s 이내인지 확인함.
- 먼저 같은 예산의 짧은 파일럿으로 R18 과 YOLOX-m 을 함께 학습함. 판정은 이 val 100장에서 FPPI 5/10 재현율과 잘 보이는 사람 재현율의
  paired bootstrap 으로 함.
- 평가 harness 의 MAX_DETS 를 300 이상으로 올림. 운영 conf 는 고정값이 아니라 목표 FPPI(예: 5~10)에 맞춰 val 에서 정함.
- 학습 데이터 라이선스 확인: CrowdHuman 은 CC BY-NC 라서 상용 모델 학습에 쓰려면 법무 확인이 필요함 (상용 가능 데이터나 자체 라벨링 고려).
- 박스 정의(전신 amodal fbox / 보이는 부분 vbox / 머리)를 서비스 목적에 맞게 먼저 정함. 아주 빽빽한 군중은 머리 박스가 재현율에 유리함.

## 6. 주의사항

- 표본이 100장이라 FPPI 2 재현율의 CI 폭은 ±5pp 정도임. 1~2pp 차이로 순위를 매기지 말 것.
- 같은 FPPI 비교는 adapter 설정을 그대로 쓴 결과임 (YOLOX 는 conf 하한 0.05 + NMS 0.45, RT-DETR/DETR 은 NMS 없음).
  FPPI 20 이상은 YOLOX 의 conf 하한 때문에 비교할 수 없음.
- GT 는 amodal 전신 박스이고 가려진 사람(vis<0.5)이 29% 라서 전체 재현율의 절대값이 낮음. 실제 목표에 가까운 것은 잘 보이는 사람 재현율임.
- 파인튜닝 후 CrowdHuman val 로 평가하면 학습 데이터와 같은 도메인이라 낙관적인 값이 나옴. 실제 서비스 사진 일부로 별도 검증할 것.
- sanity_*.jpg 에는 DETR-R50 검출만 표시됨 (첫 번째 캐시 모델). GT 정렬은 정상으로 확인함.
- 지연시간은 640 입력 기준임. 해상도를 올리면 다시 측정해야 함.
