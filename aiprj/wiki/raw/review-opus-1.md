# Review opus-1 — full app review (2026-10-10)

> Reviewer (opus), read-only. Scope: app/ (core, routers, services, templates, static), scripts/, tests/.
> Method: code read against wiki/models/*.md and wiki/decisions/002-concept-ux.md, `pytest tests -q --ignore=tests/e2e` (30 passed), live probes against http://localhost:8000.
> Every finding below was checked in code, and most were reproduced on the live server.

## Summary
- Model math checks out against the specs: preprocessing, letterbox undo, YOLOX grid decode, NMS, softmax and tokenization for all 5 models. Live outputs match the wiki reference numbers: bus.jpg gives the same 4 detections, dog.jpg gives Samoyed 0.8303, and the emotion sentences give 슬픔 0.6871 / 기쁨 0.9966. The tokenizer adds [CLS]/[SEP] and keeps [SEP] when truncating.
- No XSS: there is no innerHTML/insertAdjacentHTML anywhere. Every server or user string goes through textContent / `AP.el({text})`, and Jinja autoescape is on. The emotion text echo is never rendered.
- Static path traversal blocked: `..%2f`, `%2e%2e`, backslash and directory listing all return 404.
- Threading is handled correctly: ORT `session.run` is thread-safe, and the YuNet `setInputSize`/`setScoreThreshold`/`detect` calls are serialized under `face._lock`.
- The main risks are upload handling (event-loop blocking, decompression bombs, no request size cap) and a few frontend leaks and races.

## Findings (ranked)

### High
1. **Image decode blocks the asyncio event loop**. `app/core/imageio.py:24-56`. `read_upload_image` is `async`, but it calls PIL `open/load/exif_transpose/convert/resize` inline on the loop thread, and every image router awaits it directly (`classify.py:25`, `detect.py:28`, `pose.py:17`, `face.py:30,49-50`). Repro: while a 13000x13000 PNG was decoding, `GET /api/health` took **1.08 s** (normally about 5 ms). Three such uploads ran strictly one after another (3.8 s). Every page, static file and API call stalls during each decode. Fix: `data = await file.read(...)`, then `await run_in_threadpool(_decode, data)` with all PIL work inside `_decode`.
2. **Decompression bomb accepted (pixel count up to about 178 MP)**. `app/core/imageio.py:38-46`. PIL raises only above 2×`MAX_IMAGE_PIXELS` (about 178 MP). Between 89 and 178 MP it only warns. Repro: a 20 KB mode-"1" PNG at 13000x13000 (169 MP) returned **200**. `convert("RGB")` allocates about 500 MB, plus copies from exif_transpose. Three in a row pushed the worker working set to 1.3 GB. Fix: check `img.size` right after `Image.open` and before `load()` (for example, reject if `w*h > 40e6`). Also call `warnings.simplefilter("error", Image.DecompressionBombWarning)` or set `Image.MAX_IMAGE_PIXELS = 40_000_000`. For JPEG, use `img.draft("RGB", (1600,1600))` so the decoder downsizes during decode.
3. **No request-body size limit**. Starlette spools the whole multipart body to disk before the handler runs. `imageio.py:30` only caps what it reads afterwards. Repro: a 60 MB upload was fully received (`size_upload=60000200`) before the 413 came back. `/api/emotion` (`routers/emotion.py:18`) also reads an unbounded JSON body into memory before the 500-character check. Fix: add middleware that rejects early when `Content-Length > 9 MB` (and counts streamed bytes for chunked bodies), or set a body-size limit in a reverse proxy (uvicorn itself has no body-size option). Cap the emotion body at about 16 KB.

### Medium
4. **Pose returns 500 for extreme aspect ratios**. `app/services/pose.py:61-62`. `nw, nh = round(w*r), round(h*r)` can be 0, and `cv2.resize` then throws. Repro: 1600x1 and 1x1600 PNGs both give **500 INTERNAL_ERROR** on `/api/pose`, while classify, detect and face handle them. Fix: `max(1, int(round(...)))`, as detect.py:86 already does.
5. **Classify memory amplification on thin images**. `app/services/classify.py:54-55`. The short side is scaled to 256 before the crop, so a 1600x1 image is resized to **409600x256** (about 315 MB RGB) to extract 224x224. Repro: latency was 0.70 s (vs 0.24 s), and 8 parallel requests added about 350 MB of working set. The threadpool allows up to 40 of these at once. Fix: compute the crop box in source coordinates and use `img.resize((224,224), box=(...))`, or reject or clamp aspect ratios above about 20:1.
6. **Blob URL leak on every upload (unbounded in pose live mode)**. `app/static/js/common.js:140`. `AP.loadImage(File)` calls `URL.createObjectURL` and never revokes it. It runs twice per request: once inside `resizeImage` (`:152`) and once for display (`detect.js:76`, `pose.js:65`, `face.js:48,112`). In pose live mode that is 2 leaked blobs (about 100-300 KB each) every 1.5 s, which is hundreds of MB per hour. Fix: inside loadImage, revoke the URL in `onload`/`onerror` when it was created from a Blob.
7. **Pose live-mode race leaves the camera running**. `app/static/js/pose.js:78-99, 113`. `startLive` awaits `getUserMedia` without checking whether the checkbox is still on, and there is no guard against a second start. Toggling on, off, on quickly gives two streams and two intervals. `liveStream`/`timer` are overwritten, so the first stream and interval leak: the camera LED stays on and frames are posted twice. Fix: keep a start token. After the await, `if (!live.checked || token !== cur) { stream.getTracks().forEach(t=>t.stop()); return; }`, and call `stopLive()` at the start of `startLive`.
8. **Unbounded CPU concurrency / ORT thread oversubscription**. `services/detect.py:40-41`, `services/pose.py:40-44` use the default intra-op threads (all cores). `classify.py:37` and `emotion.py:38` use 4 threads. The Starlette threadpool runs up to 40 inferences at once, each starting its own ORT threads. Measured with 8 parallel pose requests: 0.30 s grows to 0.48 s per request (mild on 8 cores, worse on small laptops or with mixed models). Fix: a global `asyncio.Semaphore(2..cpu/2)` around `run_in_threadpool` for inference, plus `intra_op_num_threads` set to physical cores / 2 for every session, and `inter_op_num_threads=1`.
9. **Upload limit and type list differ from contract 002 §7**. `app/core/imageio.py:9,11,32`. The code uses 10 MB and the message says "최대 10MB", but the contract says ≤ 8 MB. GIF and BMP are accepted but not in the contract. Fix: either set `MAX_BYTES = 8*1024*1024` or update doc 002 (the contract is the single source of truth).
10. **Loading spinner cleared by a stale request**. `app/static/js/common.js:195-205` with `classify.js:37-41`, `detect.js:70-79`, `pose.js:59-70`. Each `AP.safe` call toggles the shared card's `is-loading`. If a user picks image B while A is in flight, A's completion removes the spinner while B is still pending. In pose, `busy=false` from A's `finally` also lets live frames fire mid-request. Fix: keep a per-card counter, or only clear loading when `my === seq`.

### Low
11. **Face recognizer lazy init is not locked**. `app/services/face.py:97, 134`. `_get_recognizer()` is called outside `_lock`. Two first requests at the same time both build a 37 MB SFace model, and one is thrown away. The race is benign but wastes about 0.5 s and about 40 MB. Fix: create it under `_lock` (as is already done for the detector).
12. **Pose load failure returns 500 instead of 503**. `app/services/pose.py:42`. `InferenceSession(...)` is not wrapped, so a corrupt or truncated model.onnx gives `INTERNAL_ERROR` instead of the contract's `MODEL_NOT_READY` 503. The other 4 services wrap it. Fix: catch the error and raise `ApiError("MODEL_NOT_READY", "모델이 아직 준비되지 않았어요", 503)`. The pose message text also differs from the contract (`"포즈 모델 파일이 없어요"`).
13. **Router import failures are swallowed**. `app/main.py:20-24`. If a router fails to import (for example, tokenizers is missing), its endpoints return 404 `NOT_FOUND` instead of 503 `MODEL_NOT_READY`, with only a warning in the log. Fix: import the routers unconditionally, since the services already import heavy deps lazily or map failures to 503. Or register a stub router that returns 503.
14. **`/api/models/status` `name` field does not match the contract**. `app/routers/system.py:24`. The contract says `name` is the model name ("<모델명>"), but it returns the service key ("classify"). The `"loading"` state is never produced. Fix: have each service's `status()` return its model name (MobileNetV2, YOLOX-tiny, YOLOv8n-pose, YuNet+SFace, KoELECTRA-int8).
15. **Emotion emoji map does not match the model's labels**. `app/static/js/emotion.js:10-14`. The model labels are `기쁨 분노 상처 불안 당황 슬픔 중립` (`models/emotion/labels.json`). The map has a `놀람` entry that never occurs and no entries for `상처` or `당황`. Those two fall back to 🙂 + `var(--accent)` = `--sun` in the emotion theme, so they flash the same yellow as 기쁨. Fix: add `상처: ['💔','var(--primary)']` and `당황: ['😳','var(--mint)']`, and drop 놀람.
16. **Emotion sample chip clicked while busy**. `app/static/js/emotion.js:32-34, 54`. The chip overwrites the textarea, but `submit()` returns early because `busy` is true. The result shown then belongs to the old text, under the new text. Fix: ignore chip clicks while busy, or queue the submit.
17. **Empty emotion result card after an error**. `app/static/js/emotion.js:56-59`. `card.hidden=false` runs before the request. On the first failure (for example, 503), the card stays visible but empty. Fix: on `!res`, hide it again if there was no previous result.
18. **Pose labels differ between client and server**. `app/static/js/pose.js:19-27` ignores the server's `people[].guess` (`services/pose.py:117-152`, `routers/pose.py:20-21`). It shows "손 흔들어요" where the server says "한 손 들기". Without a nose it says "얼굴이 가려졌어요", even when the server found cheer, t_pose or sitting. The server's t_pose and sitting are never shown. Fix: use `p.guess.label_ko` when present and keep the client heuristic as a fallback.
19. **Pose live mode spams error toasts**. `app/static/js/pose.js:64-66`. When the server is down or returns 503, `AP.safe` posts an error toast every 1.5 s. The live loop also keeps running while the tab is hidden. Fix: stop live mode (or back off) after the first error, and pause when `document.hidden`.
20. **Canvas line widths are fixed at draw time**. `app/static/js/common.js:405-408, 431-433`. `AP.canvasScale` reads `clientWidth` only when drawing, and there is no resize or orientation handler. After a window resize or phone rotation, boxes and skeletons become hairline or chunky. If a face-detect result arrives while the user is on the compare tab, the hidden panel has `clientWidth=0`, so the scale falls back to 1 and lines are thin on large images. Fix: redraw on `ResizeObserver` (detect already has `redraw()`), and redraw after `showTab`.
21. **Webcam modal can open twice / accessibility gaps**. `app/static/js/common.js:215-258, 340`. A quick double-click on 📷 starts two `getUserMedia` calls and opens two stacked modals with two streams. The modal has no focus trap and does not return focus to the trigger. Fix: an `opening` flag on the picker, a focus trap, and `btnCam.focus()` in `stop`.
22. **Accessibility basics**. In `templates/face.html:29-46`, the tabs have no arrow-key handling and no `aria-labelledby` on the panels. In `base.html:28`, the status dot has `aria-label` but no `role="img"`. Canvas results (pose/face) have no text alternative beyond the comment line. Fix: add the ARIA attributes, plus a visually hidden summary list for the detections and keypoints.
23. **Sample images referenced but missing**. `classify.js:48-51` (cat, pizza, car), `detect.js:90-91` (room, animals), `pose.js:106` (yoga). Only dance, dog, face_a, face_b and street exist. The buttons hide themselves, but every page load fires 404 fetches, and classify ships with 1 sample. Fix: add the files or remove the entries.
24. **Tests hard-code a session scratchpad path**. `tests/test_classify.py:8`, `test_detect.py:7`, `test_face.py:13`, `test_pose.py:7` point at `...\Temp\claude\...\d71c4f1c...\scratchpad`. On any other machine or session these tests `skip` silently, and the suite looks green with no model coverage. No test covers the bomb, oversize or extreme-aspect paths. Fix: commit small fixtures under `tests/data/` (or use `app/static/img/samples`), and add regression tests for items 2, 4 and 5.
25. **Model downloader does not verify checksums**. `scripts/download_models.py:27-28, 60-63`. It checks only the size, although the wiki records SHA-256 for every file. It always exits 0, even with `--check` or when a download fails, so CI cannot detect missing models. Fix: add sha256 to FILES and verify it, and return 1 when anything is missing or failed.
26. **No model warm-up (Windows CPU cold start)**. All services lazy-load on the first request. The emotion model (114 MB int8) and SFace (37 MB) make the first user request slow, and on Windows Defender's first scan it can be multi-second. During that time the home badges show "준비됨" for `not_loaded` (`index.js:21`). Fix: an optional background warm-up thread in a FastAPI `lifespan` startup hook (it must not block startup), and map `not_loaded` to "예열 중" while it runs.

## Verified OK (no action)
- Detect: BGR input with no /255, top-left letterbox, `/r` undo, grid order 8/16/32 row-major, `exp(wh)*stride`, obj×cls, class-wise NMS and clipping all match wiki/models/detection.md. Live bus.jpg results match the wiki's numbers.
- Pose: centered letterbox, RGB /255, `(x-pad)/r` undo for both boxes and keypoints, class-agnostic NMS. COCO17 names and edges match contract 002.
- Classify: resize short side to 256, center-crop 224, RGB, ImageNet mean/std, softmax in float64.
- Face: YuNet `(w,h)` order, rows reshaped to (1,15) for alignCrop, the same BGR image used for detection and alignment, largest-area face, cosine threshold 0.363. The landmark order is documented.
- Error envelope: 400/413/422/503/500 all return `{"error":{code,message}}` (checked live for MISSING_FIELD, INVALID_PARAM, INVALID_IMAGE for a text file with a fake `image/png` type, truncated JPEG, TEXT_EMPTY, TEXT_TOO_LONG, FILE_TOO_LARGE, INTERNAL_ERROR). No stack traces leak.
- Frontend field names match the router responses for all endpoints: `predictions`, `detections`/`counts`, `people`/`edges`/`keypoint_names`, `faces`, `a/b.face`/`num_faces`/`similarity_percent`/`same_person`, and emotion `label/score/scores/sentiment`.
